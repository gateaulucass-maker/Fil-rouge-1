Classement des stacks

Les quatre combinaisons du benchmark, notées critère par critère et classées sur 100. Chaque note dit d’où elle vient. La stack A reste devant, mais rien n’est encore testé.

Provisoire. Aucune note ne vient d’un test réel : tout est lu dans la documentation ou estimé à partir de ce qu’on sait. Les tests des 4 usages sont prévus le 29 octobre. Chaque résultat remplacera une estimation par une note « testé », et le classement se recalculera.

Le classement

Quatre stacks, un score sur 100

#Score total pondéré/100

Cliquer sur une stack ouvre le détail de ses 8 notes. Les stacks dont les données sortent d’Europe sont éliminées : elles gardent leur score pour information, mais ne sont pas classées.

Celle qu’on garde

Stack A · Claude Code + Supabase + n8n

C’est l’outil avec lequel on construit Le Cadre. Première du classement avec 71 sur 100, devant la stack D qui a la même base et la même automatisation.

  • Elle passe le critère éliminatoire : Supabase en région européenne, n8n à Francfort ou chez nous. Reste à choisir l’hébergement de l’appli en Europe.
  • Aucun blocage sur les webhooks, là où Glide et Zapier bloquent sans payer.
  • L’écart avec D vient de deux critères estimés : capacités et affichage. Ce sont justement ceux que les tests du 29 octobre vont mesurer.

provisoire Ce choix est une base de travail, pas une décision. Il ne vaut qu’avec les tests.

Même produit, deux descriptions. Le compte rendu de Camille écrit la stack A comme « Claude Code + React + Next + Supabase ». C’est la même stack vue de plus près : React et Next sont ce que Claude Code écrit, n8n ou les fonctions de Supabase font l’automatisation. À écrire d’une seule façon dans le rendu final.

L’échelle

Comment chaque note est donnée

Une note sans échelle ne vaut rien. Voici ce que valent 5, 3 et 1 pour chaque critère. Les notes 4 et 2 sont entre deux. Le score total est la somme des notes multipliées par leur poids, ramenée sur 100.
