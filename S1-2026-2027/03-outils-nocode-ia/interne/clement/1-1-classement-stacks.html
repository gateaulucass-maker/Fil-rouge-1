Classement des stacks

Les quatre combinaisons du benchmark, notées critère par critère et classées sur 100. Chaque note dit d’où elle vient. La stack A, en code avec React, Next.js et Supabase, reste devant, mais rien n’est encore testé.

Provisoire. Aucune note ne vient d’un test réel : tout est lu dans la documentation ou estimé à partir de ce qu’on sait. Les tests des 4 usages sont prévus le 29 octobre. Chaque résultat remplacera une estimation par une note « testé », et le classement se recalculera.

Brique par brique

Chaque outil seul, couche par couche

Une stack, c’est trois couches : ce qui construit les écrans, ce qui garde les données, ce qui automatise. Ici chaque outil est noté seul, sur les critères de sa couche, de 0 à 5. Le score de la couche est la moyenne, ramenée sur 100. C’est là qu’on voit où un critère se joue, et quelle brique on choisit. Les outils en gris ne sont dans aucune des 4 stacks : d’autres langages et services, ajoutés pour comparer.

Celle qu’on garde

Stack A · React + Next.js + Supabase

C’est avec ça qu’on construit Le Cadre. Première du classement avec 71 sur 100, devant la stack D qui a la même base. Pas d’outil d’automatisation à part : les règles sont écrites en code, dans Supabase.

provisoire Ce choix est une base de travail, pas une décision. Il ne vaut qu’avec les tests.

Pourquoi Claude Code n’est plus dans le nom. Un outil qui écrit du code n’est pas une stack : la stack, c’est ce qui fait tourner le produit. Le compte rendu de Camille dit encore « Claude Code + … ». À écrire partout de la même façon désormais : React + Next.js + Supabase, règles en code, construit avec Claude Code. Décision du 22 octobre : pas de n8n, l’automatisation se fait en code.

L’échelle

Comment chaque note est donnée

Une note sans échelle ne vaut rien. Voici ce que valent 5, 3 et 1 pour chaque critère. Les notes 4 et 2 sont entre deux. Le score total est la somme des notes multipliées par leur poids, ramenée sur 100.

Après chaque test

La note passe en « testé », la capture va dans captures-ia/ à côté de cette page, et son lien s’affiche sous le statut dans le détail. Si le code en React et Next.js échoue sur un usage ou prend beaucoup trop de temps, D passe devant : c’est le plan B.
