Celle qu’on garde

Pour l’instant : la stack A

Claude Code + Supabase + n8n

  • C’est l’outil avec lequel on va construire Le Cadre.
  • Elle passe le critère éliminatoire sur l’hébergement en Europe, d’après la documentation, et n’a pas de blocage sur les webhooks.
  • Comparée à la stack D (même base, même automatisation), la différence vient du seul outil de construction : la comparaison est claire.

provisoire Ce choix est une base de travail, pas une décision. Il ne vaut qu’avec les tests.

Ce qui peut encore la faire tomber

L’hébergement européen de l’appli construite avec Claude Code n’est pas encore choisi ni vérifié. Et si Claude Code échoue sur un des 5 tests, ou y passe beaucoup trop de temps, la stack D (FlutterFlow, même base et même automatisation) est le plan B.

Prochaine étape : jouer le test commun sur les 4 stacks (le toucher, de l’envoi à la notification de l’aidant, avec un cas invalide et un doublon), en commençant par A et D. Chaque résultat passe en « testé », avec sa capture. Détail sur la page des 4 usages.
