01 · Le scénario

5 minutes pour tout montrer

La démo raconte une journée en 5 minutes. Chaque étape montre une fonction et la promesse « rassurer sans surveiller ».

0:00

La famille envoie une photo depuis l'appli, avec une légende.

0:30

La photo arrive sur le cadre, le prénom en gros. Le senior touche le cœur.

1:00

Le téléphone de la famille reçoit « Mamie a aimé ta photo ».

1:30

Un proche appelle : sonnerie, photo, « C'est Lucas ». Le senior appuie sur Décrocher.

2:30

Le senior sort l'écran du socle et l'emporte, l'appel continue.

3:30

Bouton « parler » : « Appelle Sophie ». Le cadre demande confirmation.

4:30

Mode pause. L'aidant voit seulement « en pause » et « connecté il y a 1 min ».

Bonus si le temps le permet : montrer un deuxième cadre pas encore installé, et l'appairer en direct en scannant son QR code.

À dire à l'oral : sur une tablette du commerce, le bouton micro est logiciel et l'adaptateur aimanté n'est pas certifiable. Dans le produit final, ce seront une vraie coupure électrique et des contacts à ressort.

04 · La tablette

Verrouiller la tablette sur notre appli

Le mode « propriétaire de l'appareil » empêche de sortir de l'appli : pas de barre de notifications, pas de bouton Accueil. Seul l'aidant, avec un code, peut en sortir.

# 1. Réinitialiser la tablette, et NE PAS ajouter de compte Google à l'assistant
# 2. Activer les options développeur et le débogage USB, brancher au Mac
adb install freekiosk.apk
adb install cadre-flutterflow.apk
adb shell dpm set-device-owner com.freekiosk/.DeviceAdminReceiver
# 3. Dans FreeKiosk : application externe = notre appli cadre,
#    démarrage automatique, écran toujours allumé, code PIN pour l'aidant

Permissions à ajouter dans FlutterFlow (réglages Android, fichier AndroidManifest) :

<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.RECORD_AUDIO"/>

<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT"/>
  1. Les fonctions de kiosque, de luminosité et d'écran allumé ne marchent pas dans l'aperçu web de FlutterFlow : il faut tester directement sur la tablette (APK).
  2. La nuit, on n'éteint pas l'écran : on baisse la luminosité à 5 % et on met le diaporama en pause, pour qu'un appel reste visible.
  3. Sortie aidant : 5 appuis dans un coin, puis le code PIN (idée reprise du projet open source memory-link).
05 · Les données

La base Supabase et l'appairage

Chaque cadre est lui-même un utilisateur Supabase, rattaché à une famille. Les règles de sécurité (RLS) sont écrites dès la semaine 1 : une famille ne voit jamais les données d'une autre.

TableContenu
famillesUne famille, son nom
membresQui fait partie de la famille, avec le rôle aidant ou proche
cadresLe cadre : famille, en pause, horaires de nuit, dernier signal, batterie
contacts_autorisesLa liste blanche : qui peut appeler, validé par l'aidant (date de validation)
photosChemin dans le stockage, auteur, légende
reactionsLes « merci » du senior
messages_vocauxDans les deux sens, lu ou non
appelsQui appelle qui, salle LiveKit, statut : sonne, décroché, plus tard, terminé
appairagesCode QR à usage unique, valable 10 minutes

Les règles de sécurité clés

-- Une personne ne voit que les photos de ses familles
create policy photos_select on photos for select to authenticated
  using (famille_id in (select priv.mes_familles()));

-- Seul l'aidant peut modifier la liste blanche
create policy ca_write on contacts_autorises for all to authenticated
  using (priv.est_aidant((select famille_id from cadres where id = cadre_id)))
  with check (priv.est_aidant((select famille_id from cadres where id = cadre_id)));

-- On ne peut appeler le cadre que si on est dans la liste blanche validée
create policy appels_insert on appels for insert to authenticated with check (
  appelant_id = (select auth.uid()) and (
    cadre_id = priv.mon_cadre()
    or exists (select 1 from contacts_autorises ca
               where ca.cadre_id = appels.cadre_id
                 and ca.membre_user_id = (select auth.uid())
                 and ca.valide_at is not null)));

L'appairage par QR code

  1. Au premier démarrage, le cadre se connecte de façon anonyme et crée sa ligne dans cadres, avec un code de 8 caractères valable 10 minutes.
  2. Il affiche le QR en grand : « Demandez à votre proche de scanner ».
  3. L'aidant scanne avec l'appli famille, qui appelle la fonction ci-dessous.
  4. Le cadre voit sa famille arriver en temps réel et passe au diaporama.
create function public.revendiquer_cadre(p_code text, p_famille uuid) returns uuid
language plpgsql security definer set search_path = '' as $$
declare c uuid;
begin
  if not priv.est_aidant(p_famille) then raise exception 'non autorisé'; end if;
  update public.appairages set utilise_at = now(), utilise_par = auth.uid()
   where code = p_code and utilise_at is null and expires_at > now()
   returning cadre_id into c;
  if c is null then raise exception 'code invalide ou expiré'; end if;
  update public.cadres set famille_id = p_famille where id = c and famille_id is null;
  return c;
end $$;

« Connecté il y a X minutes »

Le cadre envoie un signal toutes les 60 secondes. L'aidant voit seulement l'état technique, jamais l'activité du senior.

create function public.ping_cadre(v text, bat int) returns void
language sql security definer set search_path = '' as $$
  update public.cadres set last_seen_at = now(), app_version = v, batterie = bat
  where device_user_id = (select auth.uid()) $$;
06 · L'appel vidéo

LiveKit dans FlutterFlow

  1. Appel entrant sur le cadre : le cadre écoute la table appels en temps réel. Quand une ligne « sonne » arrive, il affiche l'écran plein écran avec Décrocher et Plus tard. Pas besoin de notification : l'appli est toujours ouverte.
  2. Appel entrant sur le téléphone de la famille : notification push et le paquet flutter_callkit_incoming. Optionnel pour la démo : l'appli ouverte écoute le temps réel comme le cadre.
  3. Pas de décroché automatique en version 1 : le senior appuie toujours sur Décrocher.
// Widget sur mesure FlutterFlow « AppelVideo » (paramètres : url, token, cleE2ee)
import 'package:livekit_client/livekit_client.dart';
import 'package:livekit_components/livekit_components.dart';

Future<Room> rejoindre(String url, String token, String? cle) async {
  E2EEOptions? e2ee;
  if (cle != null) {
    final kp = await BaseKeyProvider.create();
    await kp.setKey(cle);
    e2ee = E2EEOptions(keyProvider: kp);
  }
  final room = Room(roomOptions: RoomOptions(
      adaptiveStream: true, dynacast: true, e2eeOptions: e2ee));
  await room.connect(url, token);
  await room.localParticipant?.setCameraEnabled(true);
  await room.localParticipant?.setMicrophoneEnabled(true);
  return room;
}
// Edge Function Supabase : crée le jeton LiveKit après avoir vérifié la liste blanche
import { AccessToken } from "npm:livekit-server-sdk";
const at = new AccessToken(Deno.env.get("LK_KEY")!, Deno.env.get("LK_SECRET")!,
  { identity: userId });
at.addGrant({ room: appel.room_name, roomJoin: true, canPublish: true, canSubscribe: true });
at.ttl = 3600;
return Response.json({ token: await at.toJwt(), url: Deno.env.get("LK_URL") });

Les noms exacts des paramètres changent selon les versions de livekit_client (v2.13 en octobre 2026) : vérifier dans l'exemple officiel du dépôt client-sdk-flutter. Décision le jour 5 : si le widget ne compile pas, on passe à la page LiveKit Meet dans une WebView.

07 · La voix

Du bouton « parler » à l'action

  1. Le senior appuie sur Parler et dit sa phrase (2 à 6 secondes).
  2. L'Edge Function voix envoie l'audio à Voxtral (0,003 $ la minute, français, avec les prénoms de la liste pour mieux les reconnaître), puis le texte à Mistral Small avec le prompt ci-dessous.
  3. L'appli vérifie que le contact est bien dans la liste blanche (on ne fait jamais confiance à l'IA seule), puis demande confirmation : « J'appelle Sophie ? Oui / Non ».
  4. Au premier usage, le cadre dit : « Je suis un assistant automatique » (AI Act, article 50).
  5. Version gratuite possible : le paquet speech_to_text d'Android en français, mais il coupe vite quand on fait une pause.
Tu es le module de commande vocale d'un cadre photo pour une personne âgée.
Tu reçois la transcription (parfois imparfaite) d'une phrase en français.
Réponds UNIQUEMENT avec un objet JSON :
{"intention": ..., "contact": <libellé exact de la liste ou null>, "valeur": <nombre ou null>,
 "confiance": <0 à 1>, "reponse_vocale": <phrase courte, vouvoiement>}
Intentions : appeler | photo_suivante | photo_precedente | lire_legende | dire_merci
             | ecouter_messages | enregistrer_message | pause | reprendre | volume | inconnu
Règles : n'invente jamais de contact ; « ma fille » → le contact marqué fille ;
si deux contacts possibles ou confiance < 0.6 → "inconnu" et demander de répéter ;
jamais de conseil médical ; pas d'appel aux secours.
LISTE DES CONTACTS : {{contacts_json}}
Exemples :
« appelle ma fille » → {"intention":"appeler","contact":"Sophie","confiance":0.95,
                         "reponse_vocale":"J'appelle Sophie ?"}
« laisse-moi tranquille » → {"intention":"pause","reponse_vocale":"D'accord, je me mets en pause."}
« appelle Bernard » (absent) → {"intention":"inconnu",
   "reponse_vocale":"Je ne connais pas Bernard. Voulez-vous appeler Sophie ou Lucas ?"}

Mesurer en semaine 2 le temps de réponse sur 20 phrases. Les études montrent que les voix âgées sont moins bien reconnues : chaque commande vocale a toujours un bouton équivalent à l'écran.

08 · L'interface

Six écrans, des règles strictes

Accueil : diaporama

Photo plein écran, prénom de l'expéditeur, légende. En bas : cœur « Merci » et « Appeler [prénom] ». Date et heure en grand.

Appel entrant

Photo et prénom, annoncé à voix haute. Deux boutons énormes : Décrocher (vert) et Plus tard. Aucun délai qui fait disparaître l'écran.

Mes proches

Grille de 4 à 8 visages avec prénom. Un appui = appel, après confirmation.

Messages

Les vocaux de la famille, lus d'un appui. Bouton « Répondre » qui enregistre.

Pause

Un écran calme : « En pause, appuyez pour reprendre ». Ni appels ni photos.

Installation

Un grand QR code et une phrase : « Demandez à votre proche de scanner ».

Les règles de l'interface

  1. Boutons de 16 à 20 mm minimum (environ 118 pixels), espacés d'au moins 3 mm, les principaux en haut ou à droite.
  2. Texte lisible à 80 cm : au moins deux fois la taille d'une tablette tenue en main.
  3. Contraste de 7 pour 1, jamais une information donnée par la couleur seule.
  4. Seulement l'appui simple : ni glisser, ni pincer, ni appui long. Un double appui compte pour un seul.
  5. Un son et un retour visuel à chaque action, sonnerie grave.
  6. Aucun menu, aucun réglage côté senior : tout se règle dans l'appli de l'aidant.

11 · Le jour J

La checklist de la démo

  1. Réseau : téléphone 4G dédié, pas le wifi invité. Un appel test 30 minutes avant. Vidéo de secours enregistrée.
  2. Matériel : tablette sur secteur dans son socle, téléphone « famille » chargé, câble USB, code PIN de l'aidant noté.
  3. Comptes : une aidante (Sophie), un proche (Lucas), un cadre « Mamie Jeanne » déjà installé, et un second cadre pas installé pour montrer le QR.
  4. Données : 25 photos avec légendes, 2 messages vocaux non lus, 3 proches validés et 1 en attente.
  5. Stripe : carte de test 4242 4242 4242 4242, webhook vérifié.
  6. Quotas : LiveKit (5 000 minutes), Scaleway et Mistral vérifiés la veille.
